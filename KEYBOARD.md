# VoiceFlow Keyboard Extension — Setup

One-time Xcode setup to wire the `ios/VoiceFlowKeyboard/` folder into
your project as a real Custom Keyboard Extension target. ~10 minutes.

Until you do this, the files in `ios/VoiceFlowKeyboard/` are just
sitting in the repo without being compiled. Everything else in the
app builds and ships via `fastlane beta` as usual — the keyboard
target is a manual one-time add.

## Why can't this be automated?

Xcode's project file format (`project.pbxproj`) is notoriously
fragile to hand-edit, and adding a full second target with its own
signing, Info.plist, embedded-extension relationship to the main
app, and shared file memberships is the kind of change Xcode really
wants to do itself via the New Target wizard. One bad character and
the project stops opening. Safer for you to click through it once.

## Prereqs

- Xcode 15+
- You have `com.hak-tx.voiceflow` bundle ID registered and working
  (you do — main app is already on TestFlight)
- You want the keyboard extension to be named `VoiceFlowKeyboard`
  with bundle ID `com.hak-tx.voiceflow.keyboard`

## Step 1 — Add the target

1. Open `ios/VoiceFlow.xcodeproj` in Xcode.
2. **File → New → Target…**
3. Scroll to **iOS** section → select **Custom Keyboard Extension** → **Next**
4. Fill in:
   - Product Name: **VoiceFlowKeyboard**
   - Language: **Swift**
   - Project: VoiceFlow
   - Embed in Application: VoiceFlow
5. **Finish**. If Xcode asks "Activate 'VoiceFlowKeyboard' scheme?" → click **Cancel** (we don't need the keyboard scheme active, just the main app's).

Xcode will create a stock `VoiceFlowKeyboard/` folder in the project
navigator with a `KeyboardViewController.swift` file it generated
itself. Delete that generated file — we're replacing it.

## Step 2 — Drop in the real keyboard files

In the **Project Navigator** (left sidebar in Xcode):

1. Right-click the generated **VoiceFlowKeyboard** group → **Delete** → **Move to Trash** the stock `KeyboardViewController.swift` that Xcode created.
2. Right-click the **VoiceFlowKeyboard** group → **Add Files to "VoiceFlow"…**
3. Navigate to `ios/VoiceFlowKeyboard/` in the file picker.
4. Select these four files:
   - `KeyboardViewController.swift`
   - `VoiceFlowKeyboardEngine.swift`
   - `KeyboardRootView.swift`
   - `VoiceFlowKeyboard.entitlements`
5. In the dialog, make sure:
   - **Copy items if needed**: unchecked (files already in repo)
   - **Added folders**: Create groups
   - **Add to targets**: check ONLY **VoiceFlowKeyboard** (NOT VoiceFlow)
6. Click **Add**.

Also replace the generated `Info.plist` the target shipped with:
1. Right-click the generated `Info.plist` inside the VoiceFlowKeyboard group → Delete → Move to Trash.
2. Add Files → navigate to `ios/VoiceFlowKeyboard/Info.plist` → Add to target: **VoiceFlowKeyboard** only.

## Step 3 — Share code with the main app

The keyboard extension needs these existing main-app files compiled
into its binary too. In the **File inspector** (right sidebar),
click each file in the main app's navigator and check the
**VoiceFlowKeyboard** box under "Target Membership":

- `ios/VoiceFlow/Secrets.swift` ← has to exist locally; autogenerated
- `ios/VoiceFlow/Core/ClaudeCleanup.swift`
- `ios/VoiceFlow/Models/TonePreset.swift`

Click each file → File inspector (⌥⌘1) → Target Membership → check
**VoiceFlowKeyboard**. Both boxes (VoiceFlow + VoiceFlowKeyboard)
should be checked for these three files.

## Step 4 — Configure the keyboard target's build settings

Click the **VoiceFlowKeyboard** target in the project settings
(click the blue project icon at top of navigator, select
VoiceFlowKeyboard under TARGETS):

### Signing & Capabilities tab
- **Automatically manage signing**: ON
- **Team**: Brian Hakel (same as main app)
- **Bundle Identifier**: `com.hak-tx.voiceflow.keyboard`
- Click **+ Capability** → add **App Groups**
- Under App Groups, click **+** → enter `group.com.hak-tx.voiceflow`
- Xcode will create the App Group in your developer portal automatically.

### General tab
- **Minimum Deployments iOS**: 17.0
- **Main Interface**: leave empty
- **Device Orientation**: Portrait only (keyboards always portrait)

### Build Settings tab (search for each)
- `Info.plist File` = `VoiceFlowKeyboard/Info.plist`
- `Code Signing Entitlements` = `VoiceFlowKeyboard/VoiceFlowKeyboard.entitlements`
- `Swift Language Version` = Swift 5

## Step 5 — Match the main app's App Group

The main app target also needs the same App Group so both targets
can share user defaults / dictation history in future work. Click
the **VoiceFlow** target → Signing & Capabilities → + Capability →
**App Groups** → + → `group.com.hak-tx.voiceflow`.

(Skip if already present.)

## Step 6 — Build and run

1. Scheme selector (top bar): make sure **VoiceFlow** is selected
   (not VoiceFlowKeyboard).
2. **Product → Archive** or `cd ios && fastlane beta`.
3. Install on your phone via TestFlight.

## Step 7 — Enable the keyboard on your phone

1. iPhone **Settings → General → Keyboard → Keyboards**
2. **Add New Keyboard…**
3. Under **Third-Party Keyboards**, tap **VoiceFlow**
4. Go back one level, tap **VoiceFlow** in the list
5. Toggle **Allow Full Access** ON
   - iOS will warn you about data access. Tap Allow.
   - Full Access is required so the keyboard can make network
     requests to the Claude API.

## Step 8 — Test it

1. Open **Messages** or **Notes** on your iPhone.
2. Tap in a text field.
3. Long-press the globe 🌐 key (or tap it repeatedly) → switch to **VoiceFlow**.
4. The keyboard will either:
   - Show the explainer ("Enable Full Access") if step 7 isn't done.
   - Show the mic button. Tap it, speak, wait for auto-stop,
     cleaned text gets inserted at your cursor.

## Troubleshooting

### "KeyboardViewController not found" at runtime
Your keyboard extension's Info.plist has
`NSExtensionPrincipalClass = $(PRODUCT_MODULE_NAME).KeyboardViewController`.
If Xcode generated a different principal class, either rename your
controller or edit the plist to match.

### "No mic permission" inside the keyboard
Keyboard extensions don't automatically inherit the main app's mic
grant. On first use, iOS prompts fresh for mic + speech permissions
while the keyboard is active. If the prompt doesn't show up:
- Settings → General → Keyboard → Keyboards → VoiceFlow → Allow Full Access must be ON.
- Settings → Privacy & Security → Microphone → VoiceFlow must be ON.

### "Polish failed: missing API key"
`Secrets.swift` didn't get compiled into the keyboard target.
Double-check step 3 — the Target Membership checkbox for
`Secrets.swift` must include **VoiceFlowKeyboard**.

### Keyboard doesn't appear in the keyboards list
The keyboard extension target must be **embedded** in the main app,
which Xcode normally does automatically on target creation. Verify:
main app target → **General tab** → **Frameworks, Libraries, and
Embedded Content** — VoiceFlowKeyboard.appex should be listed with
"Embed & Sign".

### Build number collision
If re-archiving fails with "CFBundleVersion already used", bump it
in BOTH `ios/VoiceFlow/Info.plist` AND
`ios/VoiceFlowKeyboard/Info.plist` so they match.
